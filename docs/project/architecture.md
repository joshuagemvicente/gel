# Architecture

One native Swift app talks to Ollama on localhost and runs everything else in-process. The only path off the Mac goes through the redactor.

## Targets (generated from `Gel/project.yml`)

| Target | Type | Purpose |
| --- | --- | --- |
| `GelCore` | framework | All logic with no UI: indexing, search, LLM routing, detection, redaction, policy, reports. Shared by the app, the CLI and tests. |
| `Gel` | app | SwiftUI/AppKit UI: launcher, main window, menu bar, leak overlay, voice (WhisperKit), hotkeys (KeyboardShortcuts). |
| `gelcli` | command-line tool | Drives `GelCore` from the terminal for verification: `index`, `search`, `ask`, `detect`, `redact`, `stats`. |
| `GelCoreTests` | unit tests | Detection, redaction, chunking, citation parsing. |

Settings: Swift language mode 5 with minimal concurrency checking, macOS 15.0 deployment target, ad-hoc signing, no sandbox (needed for the global hotkey, clipboard paste and arbitrary folders). Packages: WhisperKit (app), KeyboardShortcuts (app). SQLite comes from the system (`import SQLite3`).

## Data flow

1. **Index (F1):** folder → `TextExtraction` (PDF text; OCR for pages with under 20 characters of text, and for images; DOCX) → `Chunker` (~700 chars, 120 overlap, UTF-16 offsets) → `Embedder` (`bge-m3`, prefix `File: <name> (page n)`) → `Store.save` (one transaction per file).
2. **Ask (F3):** question → embed (`Question: …`) → vector top 40 + FTS5 BM25 top 40 → reciprocal-rank fusion (k = 60), max 2 chunks per file, top 8 → prompt with numbered sources → `ModelRouter.chat` (streamed) → parse `[n]` → `Citation`s → history + `query` event.
3. **Detect/redact (F4):** text → layer 1 (pack regexes) + layer 2 (`NLTagger` names) → optional layer 3 (LLM JSON spans via `ModelRouter.completeJSON`) → `merge` (longest span wins; specific beats generic on ties) → placeholders or burned-in boxes.
4. **Leak catch (F5):** clipboard text → layers 1+2 only (instant, offline) → overlay → safe paste of placeholder text.

## Storage (SQLite at `GelPaths.database`)

| Table | Holds |
| --- | --- |
| `documents` | path (unique), kind, page_count, modified, indexed, has_ocr |
| `pages` | doc_id, page, text, lines (JSON `[PageLine]` for OCR pages: text, normalized rect with bottom-left origin, start offset) |
| `chunks` | doc_id, page, start, length (UTF-16), text, embedding (Float32 blob, L2-normalized) |
| `chunks_fts` | FTS5 (text, chunk_id) |
| `history` | question, answer, citations JSON, provider, model, sent payload (cloud only) |
| `events` | ts, kind (`query`, `leak_caught`, `leak_item`, `redaction`, `redaction_item`, `cloud_call`), category, count, app, provider. **No content.** |
| `redactions` | source path, output path, counts JSON |

The vector cache is loaded lazily into memory and invalidated on every write.

## Model routing (summary; full rules in `docs/features/model-fallback/spec.md`)

- One `OpenAICompatibleClient`, two base URLs: local `http://localhost:11434/v1` (Ollama), cloud = user's URL.
- Local chat model `qwen3:4b-instruct-2507-q4_K_M`; embeddings `bge-m3` via Ollama's native `/api/embed`; `keep_alive` 60 min; warm-up on launch.
- Fallback triggers: unreachable, HTTP error, no first token within 8 s, over 30 s total, empty response. Then 60 s cooldown on cloud.

## Demo data

`demo-data/` is generated by `scripts/.venv/bin/python scripts/generate_demo_data.py` (deterministic). `HR Files/` (20 resumes, 15 201 files, 10 payslips, 3 DOCX contracts, 10 scans — 5 JPG + 5 image-only PDFs), `Personal/` (5 PDFs + 2 scanned JPGs), `clipboard-samples/` (4 TXT), `ground_truth.json` (every planted value with type and page, plus `demo_answers`). The demo question's answers are **Reyes** (`Resume_REYES.pdf`, payroll on page 2), **Santos** and **Cruz**.
