# Decisions

Newest last. Each entry: what was decided, why, and what it affects. Add an entry the moment a decision is made or the build deviates from a spec.

| ID | Decision | Why | Affects |
| --- | --- | --- | --- |
| D-001 | Native macOS app in Swift/SwiftUI | Launcher must feel instant and native; Vision/PDFKit/NaturalLanguage are built in; user knows Swift | all |
| D-002 | Local LLM via Ollama, not Apple Foundation Models | The Mac runs macOS 15.8; Foundation Models needs macOS 26 | model routing |
| D-003 | One `OpenAICompatibleClient` for local and cloud | Ollama serves an OpenAI-compatible `/v1`, so the fallback is just a second base URL | model-fallback |
| D-004 | Cloud fallback for LLM tasks only, redacted input only, automatic with a visible badge | Local is the core of the theme; the user supplies an OpenAI-compatible endpoint (a Claude gateway) | F3, F4, settings |
| D-005 | Detection layer 3 may fall back to the cloud, but only on text redacted by layers 1–2 | User decision: local is primary, the endpoint is the fallback | F4 |
| D-006 | HR first (B2B), Personal pack for B2C, packs as JSON config | Judges reward a clear target user; packs show the platform; B2B is the priority | F7, F8, pitch |
| D-007 | F6 Finder selection cut; Library multi-select Redact replaces it | Saves time; the main window already lists files | F6, UI features |
| D-008 | Two surfaces: top-center launcher + Wispr Flow-style main window, Dock app + menu bar | User request; the viewer and modules need a real window | UI features |
| D-009 | Local chat model `qwen3:4b-instruct-2507-q4_K_M` instead of `qwen3:4b` | `qwen3:4b` is a thinking build that ignored `think:false`/`/no_think` and took 45 s for a one-line answer; the instruct build runs at ~24 tok/s with no preamble | model routing, disclosures |
| D-010 | Add a `GelCore` framework and a `gelcli` tool (not in the original plan) | Lets every engine feature be verified from the terminal and in unit tests before the UI exists | architecture |
| D-011 | Generate the Xcode project with XcodeGen (`Gel/project.yml`) | Reproducible, diffable, agent-editable; never hand-edit `.xcodeproj` | build |
| D-012 | Built F4/F7/F8 engine code before F2/F5 UI | The cloud fallback's redaction gate depends on detection, and the gate had to exist with the router | build order |
| D-013 | Extra patterns: `P18.000.00`-style amounts and bare `###-####-###(##)` bank accounts | OCR reads ₱ as "P" and may use "." separators; the dataset prints account numbers without an "account" label | F4, packs |
| D-014 | Overlap merge prefers specific types over generic ones (`PHONE`, `AMOUNT`, `NAME`, `OTHER`) at equal length | A GCash number is also a phone number; the specific label is more useful | F4 |
| D-015 | Swift 5 language mode, minimal concurrency checking | Avoid strict-concurrency friction under hackathon time pressure | build |
| D-016 | Folder watching by 5 s rescans instead of FSEvents | Simpler and robust; meets the 10 s requirement | F1 |
| D-017 | DOCX/TXT redaction outputs a placeholder `.txt`, not a PDF | Laying out DOCX into PDF is costly; DOCX is low in the cut order | F4 |
| D-018 | Spec-first workflow: specs agreed before building | User request, for a shared understanding of what is built | process |
| D-019 | Launcher hotkey stays ⌥Space; the leak demo uses chatgpt.com in Chrome | The ChatGPT desktop app also binds ⌥Space; ⌥Space is the familiar launcher key | launcher, demo |
| D-020 | `Gel.xcodeproj` stays git-ignored; judges run `xcodegen generate` | User decision; `project.yml` is the single source of truth | README, conventions |
| D-021 | One folder per feature in `docs/features/<feature>/` with role, context, spec, tasks, and interfaces (engine) or design (UI); project-wide docs in `docs/project/` | User request: feature-by-feature briefs clear enough for an AI model to build from | process, docs |
| D-022 | Search falls back to keyword-only when embedding fails | Without it, stopping Ollama breaks search before the router can reach the cloud, so the fallback could never answer (found while writing the docs) | query-citations, model-fallback |
| D-023 | JSON tasks: one 25 s local timeout, fall back on any local error | Non-streaming calls have no first-token signal | model-fallback, detection-redaction |
| D-024 | Redaction and Leak Guard events are logged by the app flows, not by `Redactor`/`PIIDetector` | Keeps the engine side-effect free; the UI knows the user's choices (kept values, app name) | redactions-module, leak-guard, home |
| D-025 | Keyword search drops English/Tagalog stopwords (incl. "years") | Measured: the demo question's BM25 matched "may" (May dates), "ang", "sino", "years" and missed Reyes entirely; "payroll" alone finds Reyes p.2, Santos, Cruz | query-citations |
| D-026 | Passage selection is diversity-first (one chunk per file, then second chunks) | Measured: with a flat 2-per-file cap, Cruz and Santos took 4 of 8 slots and Reyes's page-2 chunk fell off; "which applicants…" questions need breadth | query-citations |
| D-027 | Keyword results weigh 2× in rank fusion | Measured: bge-m3 ranks Reyes's payroll chunk outside the vector top 40 for the Taglish demo question while BM25 ranks it 6th; exact terms (payroll, SSS, names) matter most in HR files | query-citations |
| D-028 | Non-code deliverables (S1–S7) get their own folders in `docs/deliverables/`, same file format as features; X only (no LinkedIn); Claude writes and edits, the user records, posts, tests and submits | User request: spec-first for the submission, video, post, pitch, Q&A, run sheet and People's Choice | docs, submission, demo |
| D-028 | Top 6 files × up to 2 chunks each (≤ 12 passages); "not found" only when no source answers; list only matches | Measured: with 8–10 single-chunk slots, Santos's experience chunk never got in (his skills chunk did) and the model appended the not-found line after a correct partial answer | query-citations |
| D-029 | Cold-start first-token limit of 45 s when the model isn't loaded | Measured: the first `ask` after a model unload timed out at 8 s while Ollama loaded the model | model-fallback |
| D-030 | Measured on the M2: indexing 58 demo files (incl. 10 OCR scans) 25.5 s → 169 chunks; re-index 0 files in 0.02 s. Demo question (final retrieval, temperature 0): new prompt ~9–10 s to first token and ~16 s total; repeated prompt 0.2 s first token, 6.3 s total (Ollama prompt cache); cold model load 13.5 s to first token | Honest numbers for the README and pitch; rehearse the demo question once before going on stage | demo, README |
| D-031 | Retrieval = top 5 files by sum of their 2 best chunks; one numbered source per file; temperature 0 (supersedes D-026/D-028 selection) | Measured: per-chunk slots let letters/201 files that mention "payroll" once displace resumes; the 4B model mis-cited when one file appeared as several sources; temperature 0 makes the demo repeatable | query-citations |
| D-032 | Default first-token timeout 15 s (was 8 s) | Measured: a ~2,500-token prompt took ~8 s to the first token with the model warm on the M2, which falsely triggered the fallback | model-fallback, settings |
| D-033 | Code strips the "not found" sentence from cited answers; prompt shows year arithmetic by example | Measured: qwen3 4B appended the sentence after a correct 3-name answer every run and said 2017–2024 = 9 years | query-citations |
| D-034 | Recall fixes from `gelcli check`: DOB labels may carry a parenthetical; cards match 4-digit groups (not a greedy digit run); Personal pack catches amounts without ₱; names also found on a title-cased copy and via honorific/label patterns | Measured baseline: IDs/phones/emails/addresses/accounts 100%, names 31.8%, DOB 66.2%, card 66.7%, scans 89.4% | detection-redaction, packs |
| D-035 | Name propagation within a text (variants sharing ≥ 2 name parts with a found name or an email local part) | After D-034, names were 40.8%: the tagger finds a name once but misses its variants; the cloud gate relies on the fast layers | detection-redaction |
| D-036 | Measured detection/redaction (M2): `gelcli check` fast-layer recall — all ID types, cards, phones, emails, addresses, bank accounts, salaries 100%; DOB 87.3%; names 73.1%; scans (non-name) 89.4%. Layer 3 on a 201 file 15 s; degraded (no LLM) 1.5 s.
